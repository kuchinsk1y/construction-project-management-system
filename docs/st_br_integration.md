# ERP ↔ ST_BR — интеграционный API

Статус: **доплаты готовы**. Остальное (объекты, виды работ, прогресс, приём рапортов) — в согласовании.

## Общее

| Что | Значение |
|---|---|
| Базовый адрес | `https://<домен API ERP>` (локально `http://localhost:3000`) |
| Аутентификация | заголовок `x-api-key: <ключ>`; ключ ST_BR хранится в ERP в переменной `ST_BR_API_KEY`, у ST_BR — только на бэкенде |
| Формат | JSON, `camelCase` |
| Даты | `YYYY-MM-DD`, рабочий день по времени Польши (Europe/Warsaw) |
| Время | ISO 8601 в UTC (`2026-11-04T10:04:53.418Z`) |
| Деньги | число с точкой, PLN |

Ошибки — стандартный JSON NestJS: `{ "statusCode": 400, "message": "…", "error": "Bad Request" }`.

| Код | Когда | Что делать ST_BR |
|---|---|---|
| `200` | данные | — |
| `400` | неверные параметры (формат даты, период больше 62 дней, `dateTo` раньше `dateFrom`) | не повторять, исправить запрос |
| `401` | нет ключа или ключ неверный | не повторять, проверить ключ |
| `503` | ключ ST_BR не настроен в ERP | повторить позже, сообщить администратору ERP |
| `5xx`, таймаут | ERP недоступна | повторить с растущей паузой, показать последние полученные данные |

## Доплаты — `GET /v1/integration/surcharges`

ERP — единственный владелец доплат: ставки, периоды действия и включение задаёт администратор ERP (Ustawienia → Dopłaty). ERP сам решает, какие доплаты действуют в какой день; ST_BR только показывает результат и не пересчитывает его.

В ответе — только **активные** доплаты, чей период пересекается с запрошенным.

**Параметры (одно из двух):**

| Параметр | Описание |
|---|---|
| `date` | один день. Без параметров — сегодня (Польша). |
| `dateFrom` + `dateTo` | период, максимум 62 дня включительно |

**Запрос:**
```
GET /v1/integration/surcharges?dateFrom=2026-11-03&dateTo=2026-11-05
x-api-key: <ST_BR_API_KEY>
```

**Ответ `200`:**
```json
{
  "dateFrom": "2026-11-03",
  "dateTo": "2026-11-05",
  "generatedAt": "2026-11-04T10:04:53.418Z",
  "surcharges": [
    {
      "id": "6a82f8aa-c2af-4654-9df5-94eb29c5ff45",
      "name": "Trudne warunki",
      "ratePerHour": 5.5,
      "currency": "PLN",
      "validFrom": "2026-11-01",
      "validTo": null,
      "updatedAt": "2026-11-04T10:04:53.000Z"
    },
    {
      "id": "0c1e…",
      "name": "Praca w weekend",
      "ratePerHour": 8,
      "currency": "PLN",
      "validFrom": "2026-11-05",
      "validTo": "2026-11-06",
      "updatedAt": "2026-11-04T10:04:53.000Z"
    }
  ],
  "days": [
    { "date": "2026-11-03", "surchargeIds": ["6a82f8aa-c2af-4654-9df5-94eb29c5ff45"] },
    { "date": "2026-11-04", "surchargeIds": ["6a82f8aa-c2af-4654-9df5-94eb29c5ff45"] },
    { "date": "2026-11-05", "surchargeIds": ["6a82f8aa-c2af-4654-9df5-94eb29c5ff45", "0c1e…"] }
  ]
}
```

| Поле | Описание |
|---|---|
| `surcharges[]` | справочник доплат, действующих хотя бы в один день периода |
| `ratePerHour` | ставка за час, PLN |
| `validTo` | `null` — без даты окончания |
| `updatedAt` | когда доплату последний раз меняли в ERP — по нему удобно обновлять кэш |
| `days[]` | по каждому дню периода — какие доплаты действуют (`id` из `surcharges`) |

**Кэш на стороне ST_BR:** можно хранить ответ и обновлять раз в несколько минут или при открытии дня. Если ERP недоступна — показывать последние полученные данные с отметкой времени `generatedAt`.

**Проверка из консоли:**
```bash
curl -s -H "x-api-key: <ST_BR_API_KEY>" "https://<домен API ERP>/v1/integration/surcharges?date=2026-11-04"
```

## Дальше (на согласовании)

- `GET /v1/integration/projects` — объекты (уже есть, общий для интеграций).
- `GET /v1/integration/projects/:id/work-types` — виды работ с единицей, планом и выполненным объёмом.
- `GET /v1/integration/progress` — сколько сделано по дням, видам работ и работникам.
- `GET /v1/integration/projects/:id/open-days` — за какие дни можно вносить данные.
- `POST /v1/integration/reports` — приём рапорта (UUID от ST_BR как ключ идемпотентности, повторная отправка не создаёт дубль).
